# Asset Models

An **Asset Model** groups identical, individually tracked units under one shared template, for example "Dell Latitude 5550" or a fleet of the same camera body. Every unit remains its own asset with its own QR label, custody chain, and history; the model is the family it belongs to. A model can hold default values, a category, a value and any of your custom fields such as Brand or Supplier, and they fill the empty fields of every asset that joins it, so fleets stay consistent as they grow.

This sits between the two tracking methods in Shelf: [individually tracked assets](/features/asset-pages), where each item is unique, and [quantity-tracked assets](/glossary/quantity-tracked-assets), where interchangeable stock is one record with a count. Asset Models give you fleet-level convenience without giving up per-unit identity.

---

## Why group units under a model

- **Consistent records**: units that join the model get its defaults in their empty fields, so a fleet of 30 laptops does not drift into 30 slightly different records. See [Default values](#default-values).
- **One picture for the whole fleet**: upload a photo once on the model and every unit that has no photo of its own shows it.
- **Per-unit accountability stays intact**: each unit keeps its own QR label, custody, maintenance reminders, and audit trail, so you always know exactly who has which unit. Joining, leaving or switching a model is part of that trail: the unit's activity names the model it left and the one it joined.
- **Book by model**: reservations can target the model instead of a specific unit.
- **See the fleet at a glance**: the asset index's **Asset model view** lists your models instead of your assets, with how many units match your filters and where they are right now (in, out, in custody). Click a count to see the units behind it. The asset search matches model names too, so typing a model's name finds every unit of it. See [Asset Model View](/knowledge-base/advanced-asset-index-complete-guide#asset-model-view).
- **Group a fleet you already own**: select the units in the asset index, then **Actions → Update asset model**. You can create the model from inside the picker, and **Remove from asset model** ungroups a selection the same way. The model's defaults fill the empty fields of the grouped units, values they already have and custody stay as they are, and quantity-tracked assets in the selection are skipped rather than blocking the batch. See [Using Batch Actions in Shelf](/knowledge-base/using-batch-actions-in-shelf#grouping-a-fleet-into-an-asset-model). If you are changing several fields at once, an `Asset model` column in [Bulk Updating Assets via CSV](/knowledge-base/bulk-updating-assets-via-csv) does the same job as part of a wider edit, matching names case-insensitively and creating a model that doesn't exist yet.

## Default values

Under **Workspace settings → Asset models**, a model's form holds a **Default category**, a **Default valuation** and a **Default custom field values** section with one row per custom field of your workspace. Fill in what every unit of the model shares, such as the brand, the supplier or the warranty length.

![The asset model form's Default custom field values section: one row per custom field, with the note that defaults fill empty fields only and that yes/no fields can't have a default](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/asset-model-default-field-values.webp)

The rule is the same wherever an asset joins the model: creating an asset from it, bulk-creating units, picking the model on an asset's edit form, **Actions → Update asset model** on a selection, an import, or an `Asset model` column in a CSV update. Each default fills the matching field **only if it is empty**. Nothing the asset already holds is replaced, and nothing stays linked afterwards: the asset can change the value, and editing the model later does not rewrite its units.

- **On the asset form** the model's default value and custom field values appear in the empty inputs as soon as you pick the model, so a required field the model covers does not block the save. Pick a different model and only the values the first model put there change.
- **A field limited to some categories** is filled only for assets in one of them. The category is settled first, so a default category can make such a field apply.
- **Yes/no fields** can't have a default, because the form always submits them.
- **Each filled asset gets a note** on its activity naming the model and the values, for example *filled empty fields from the asset model Dell Latitude 5550: value US$450.00, Brand Dell.* A bulk grouping also says in its message how many assets the defaults filled.

**Units already in the model.** Defaults fill assets as they join. When units already in the model have empty fields its defaults could fill, the model's edit page says how many, field by field, with a **Fill empty fields on N assets** button. It fills only fields that are empty and never replaces a value.

## Book by model

With units grouped under a model, a booking can reserve a quantity of that model without picking units up front: reserve "4x HDMI cable", and at pickup staff scan whichever 4 physical units they hand out. Any unit of the model fulfils the reservation, and the booking records exactly which units went out. The reserved units are held for those dates: once reservations take up every free unit, another booking can't claim one by picking it by name, and the booking picker marks those units **Reserved by model**. You can also start from the asset index: tick models in the **Asset model view** and use **Book selection** to create a booking that reserves them, or to add them to an open one. Bookings, including reserving by model, are part of the Team plan.

A unit answers a reservation whether you pick it on its own or it arrives inside a [kit](/knowledge-base/kits) — a camera in a case is the same camera — and each physical unit answers at most one reserved unit per booking. Rows that answered one carry a blue **Fulfils _model name_** chip on the booking.

A reservation you cannot fill completely does not stop the booking. Shelf names the units still unassigned in a confirmation, checks out what is ready, and leaves the reservation open on the ongoing booking to be scanned in later or released. The quantity stays adjustable for as long as the booking is live, down to the units already assigned to it. See [Adjusting or releasing a reservation](/knowledge-base/adding-assets-and-kits-to-a-booking#adjusting-or-releasing-a-reservation).

## One cover image for the whole fleet

A model carries an optional **Image**, set under **Settings → Asset models** when you create or edit the model. It accepts PNG, JPG, JPEG, and WebP up to 8 MB.

Shelf then picks the picture an asset displays in this order:

1. the asset's own image, if it has one
2. otherwise its model's cover image
3. otherwise the standard placeholder

Nothing is copied onto the individual records. The model holds one file and every unit without a picture of its own points at it, which has four practical consequences:

- **Replacing the model's image updates every unit that inherits it**, right away. The form tells you the reach before you upload: *"Used by 12 assets that don't have an image of their own."*
- **A unit's own photo always wins.** Upload a picture on one laptop of the fleet and only that laptop changes. The model's image is never overwritten.
- **Ungrouping is clean.** Take a unit out of the model, or delete the model, and that unit falls back to its own photo, or to the placeholder if it never had one.
- **It shows everywhere the asset does**: the asset index and the asset page, the home dashboard's newest assets, Quick find, kit and location lists, the booking overview and its assets sidebar, the check-in and check-out scan pages, the result you get from scanning a QR code or a barcode, audits, reports, the booking PDF, and the Shelf Companion app on your phone. The one place it does not reach is an asset list embedded inside a note, which carries no model data.

On an asset's own edit form, **Use the model's image instead** drops that asset's photo so it follows the model again. An asset with no model image behind it gets **Remove image**, which clears the photo back to the placeholder.

This also reaches fleets you import. A CSV still cannot carry photos, but if the rows name an asset model that has a cover image, the imported units show it the moment they land.

## Asset Models vs Quantity Tracking

| | Asset Models | Quantity tracking |
|---|---|---|
| **Record** | One per unit, grouped under a model | One per pool of identical units |
| **QR labels** | Every unit has its own label | One shared label for the pool |
| **Who has it** | Exactly which unit each person holds | How many units each person holds |
| **Bookings** | Reserve "4x" of a model, scan any 4 at pickup | Reserve 4 out of 200 from the pool |
| **Change later** | Units can join or leave a model anytime | Fixed as quantity at creation |

Two rules to remember: models group individually tracked items only (a quantity-tracked pool cannot join a model), and while model grouping can be changed at any time, the underlying individual-or-quantity choice is fixed when an item is created.
