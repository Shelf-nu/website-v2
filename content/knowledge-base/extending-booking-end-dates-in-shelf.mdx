## Overview

The "Extend Booking End Date" capability allows users to lengthen existing booking durations without requiring new booking creation. This is particularly valuable for situations where assets are needed for longer than initially planned, reducing administrative work and maintaining accurate tracking within Shelf's booking system.


![Extend booking end date modal in Shelf](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/extending-booking-1.webp)
## Feature Availability

This functionality applies to bookings with these statuses:

- **CHECKED OUT** (Ongoing bookings)
- **OVERDUE** (Bookings exceeding their end date)

The "Extend Booking" option remains unavailable for **RESERVED** status bookings. Reference the [Introduction to Bookings](/knowledge-base/introduction-to-bookings) documentation for details about different booking statuses.

## How to Extend a Booking

1. Navigate to the specific booking requiring extension
2. Find the "Actions" dropdown menu on the booking details page
3. Select "Extend Booking" from available options
4. A modal appears allowing new end date selection
5. Choose the desired future end date and confirm
6. The system updates the booking with the new end date

## What Happens When You Extend a Booking

### For OVERDUE Bookings

- Booking status transitions from **OVERDUE** to **CHECKED OUT**
- Fresh reminders schedule based on the new end date:
  - Check-in reminder
  - Overdue reminder

### For CHECKED OUT Bookings

- Booking maintains **CHECKED OUT** status
- All existing scheduled reminders reschedule per the new end date:
  - Check-in reminder
  - Overdue reminder

## Notifications

Upon extending a booking, an email notification is sent to the relevant team members informing them of the extension and the new end date. This ensures transparent communication regarding asset availability.

## What Extending Does Not Change

Extending moves the booking's live end date. It does not move the **planned** end date. That one is recorded when the booking is created, still moves with any edit made while the booking is a draft, and is fixed from the moment the booking is reserved.

That distinction is what the [Booking Compliance report](/knowledge-base/getting-started-with-reports#how-booking-compliance-decides-on-time-or-late) measures against. A booking that was due Friday and is extended to Monday leaves Overdue Items straight away, because it is no longer late against its current deadline. When it comes back on Monday it is still recorded as a late return, because the deadline it was agreed to was Friday. Extending keeps operations moving; it is not a way to clear a late return from the record.

## Data Export Considerations

The booking CSV export carries both periods in four columns: **Planned start date** and **Planned end date** hold what was agreed, **Actual start date** and **Actual end date** hold where the booking finished up. On an extended booking the two end dates differ, so the full history is preserved.

The booking's PDF overview shows an **Original period** row underneath the booking period whenever the two differ.

## Use Cases

Booking extension supports various scenarios including:

- Equipment loans requiring extended duration
- Unexpected project timeline modifications
- Production delays necessitating continued asset access
- Preventing unnecessary duplicate bookings for identical assets
- Streamlining shared resource management

## Permissions

Owners, Administrators and Self-service users can extend a booking. Base users cannot: the **Extend Booking** action does not appear for them. Consult the [user roles and permissions](/knowledge-base/user-roles-and-their-permissions) documentation for additional permission details.
