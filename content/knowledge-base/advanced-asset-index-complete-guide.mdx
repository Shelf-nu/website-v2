The Advanced Asset Index gives you powerful ways to filter, sort, customize columns, and act on assets in bulk. This guide covers how to enable it, every feature, and common workflows.

## Enabling the Advanced Index

The Advanced Asset Index is a beta feature you enable per-workspace.

![Assets index in simple mode, with the Advanced toggle in the lower-right](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/enable-advanced-1.webp)

1. **Navigate to the Assets index** and locate the **Advanced (beta)** button in the lower-right corner
2. **Click the button** to accept the beta flag — there's no risk, you can toggle back to simple mode at any time
3. **You're done** — the advanced features become available immediately

![Assets index after enabling advanced mode, showing the extended toolbar](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/enable-advanced-2.webp)

> **On a phone, advanced mode steps aside.** Below tablet width the index says *"Advanced mode is currently not available on mobile"* and offers a **Change to simple mode** button. The setting is per workspace, so switching to simple on your phone switches it on your desktop too. Simple mode is the one to use on a small screen; everything in this guide is a desktop or tablet feature.

> **Feedback and requests**: the team welcomes suggestions about batch actions, column configuration, and filters. Email [hello@shelf.nu](mailto:hello@shelf.nu) or contact your account manager.

## Managing Your View


![Advanced index view](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/advanced-index-1.webp)

![Filter panel](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/advanced-index-2.webp)
### Columns Management

- Fixed column: "Name" is always visible
- Toggle any available columns including custom fields
- Drag a column by its ⠿ handle to reorder it. Dragging from the label does nothing, so a click cannot move a row by accident. With the keyboard, Tab to a handle and press **Alt + ↑** or **Alt + ↓**
- "Select all" or "Deselect all" for quick configuration

**Pro tip**: Show only necessary columns for your current task to maintain a clean view.

### Every Column You Can Show

**Name** is fixed and always first. Everything below it can be switched on or off and dragged into the order you want. The **Shown by default** column is what a brand-new workspace starts with, not a limit: switch any of them on whenever you need it.

| Column | Shown by default | What it holds |
|---|---|---|
| **Asset ID** | Yes | The workspace's own sequential ID, `SAM-0017` style |
| **QR ID** | Yes | The ID printed on the Shelf QR label |
| **Status** | Yes | Available, In custody, Checked out. A quantity-tracked pool can also read Partial custody, Partially checked out, Reserved or Partially reserved, worked out from the same figures as Free now |
| **Free now** | Yes, when the workspace has quantity-tracked assets | Units you could hand over today, as *14 of 20 pcs*: the total less custody, kits and units out on bookings. Units promised to a future booking are not subtracted. A dash on individually tracked assets |
| **Stock status** | Yes, when the workspace has quantity-tracked assets | **Short by N**, **None free**, **Running low** (at or below Min quantity) or **Enough**. Without a Min quantity it can still read **Short by N** or **None free**; otherwise it shows a dash. Hover for the figures. See [Stock columns on the asset list](/knowledge-base/quantity-tracked-assets-and-consumables#stock-columns-on-the-asset-list) |
| **Description** | Yes | Truncated to fit the row. Hover for the first 600 characters; a longer description ends with *Open the asset to read the full description* |
| **Value** | Yes | Per-unit value. On a pooled asset this is the value of one unit, not the stock |
| **Available to book** | Yes | Whether the asset can go on a booking at all |
| **Created at** | Yes | When the asset record was made |
| **Updated at** | Yes | Last change to the record |
| **Category** | Yes | One category per asset |
| **Tags** | Yes | Two shown, the rest behind `+N` |
| **Location** | Yes | Where the asset is. Pooled stock can sit in several, so this can overflow |
| **Kit** | Yes | The kit the asset belongs to |
| **Custody** | Yes | Who is holding it |
| **Upcoming Reminder** | Yes | The next [asset reminder](/knowledge-base/asset-reminders) due |
| **Upcoming Bookings** | Yes | Bookings this asset is committed to |
| **Last audit date** | Yes | When the asset was last counted in a completed audit, or *Never audited*. Owners, Administrators and Managers only, and it needs the Audits add-on. See [Last audit date](#last-audit-date) |
| **Actions** | Yes | The per-row menu |
| **ID** | No | Shelf's internal record ID, the one the [bulk update](/knowledge-base/bulk-updating-assets-via-csv) flow matches rows on |
| **Total quantity** | No | Units owned, as a bare number, for [quantity-tracked](/knowledge-base/quantity-tracked-assets-and-consumables) assets |
| **Unit of measure** | No | The pool's unit (`pcs`, `rolls`). Switched on automatically for anyone who already showed the quantity column |
| **Reserved** | No | Units promised to upcoming bookings; an over-committed pool reads like *12 · 2 short*. On an individually tracked asset, how many upcoming bookings claim it |
| **Min quantity** | No | The low-stock threshold |
| **Tracking method** | No | Individually tracked or quantity-tracked |
| **Asset model** | No | The [asset model](/glossary/asset-models) the unit belongs to |
| **Code128**, **Code39**, **DataMatrix**, **External QR**, **EAN-13** | Yes, when barcodes are on | One column per barcode type. See [Alternative Barcodes](/knowledge-base/alternative-barcodes) |
| Your custom fields | Added switched on | One column per **active** field you have defined |

The five barcode columns only exist once **Alternative Barcodes** is enabled on the workspace. They are added switched on, so they appear the first time you look after enabling.

Custom-field columns follow the same rule and follow the field itself. Creating an active field adds its column for everyone, switched on; deactivating the field removes the column again; reactivating or renaming it keeps whatever visibility and position you had chosen. A field created as inactive gets no column until you activate it. See [Adding Additional Fields to Assets](/knowledge-base/adding-additional-fields-to-assets#what-active-and-inactive-do-to-your-asset-index-column).

**Total value** is not in this list, and that is on purpose. It is written into CSV exports as a separate column, so a pooled asset's per-unit **Value** and its total both reach the spreadsheet, but it is not a column you can put on screen. See [Exporting Data from Shelf](/knowledge-base/export-exporting-workspace-data-from-shelf).

### When a Cell Holds More Than It Can Show

A table cell sets the height of its row, so a cell that stacked everything it held would stretch every other column in that row with it. Columns that can hold several values cap what they render on one line and collapse the rest into a small `+N` control:

- **Tags** and the five **barcode** columns show two, then `+N`
- **Location**, **Kit** and **Custody** show the primary one, then `+N`

Hover or tab to a `+N` and it lists what is hidden. On a barcode column it does more than that: clicking `+N` opens the code preview on the first hidden barcode, and the dialog's own selector reaches the rest, so a code past the cap is still one click from being displayed large enough to scan off the screen.

This is why a row stays the same height whether an asset carries one barcode or six.

### Last audit date

Since 20 October 2026 the index has a **Last audit date** column, switched on by default. It answers "when was this asset last counted?" without opening the audits area: the cell holds the completion date of the most recent **Completed** or **Archived** [audit](/knowledge-base/run-your-first-audit) the asset was part of, and *Never audited* when there is none. An asset the audit reported as **Missing** still counts as audited, because it was on the list that was checked.

![The advanced asset index with the Last audit date column, and the hover card on one date listing the asset's two recent audits with their result and a View all audits button](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/last-audit-date-column.webp)

Hover a date and a card lists up to three **Recent** audits (name, completion date, and whether this asset was found, missing or unexpected in it) and up to three **Upcoming** ones (pending audits with their due date, or *In progress* for an active one), each a link to the audit. **View all audits** opens the audits list filtered to that asset, with an **Asset:** chip you can remove; the list includes archived audits unless you also pick a status. An asset with no recent and no upcoming audits shows the card with *No audits for this asset*. The asset's own page carries the same history on a **Last audit** card; see [Where to see an asset's audit history](/knowledge-base/run-your-first-audit#where-to-see-an-assets-audit-history).

**Filter** on the column with the usual date operators (**is**, **is not**, **before**, **after**, **between**, **in dates**) plus one of its own, **Never audited**, which takes no date. **Sort** on it and the never-audited assets go last, whichever direction you choose. A **Standard** export carries the column when it is visible or you pick **All columns**; an **Import-ready** export never does, because an audit date is not something you can import. Both formats respect a Last audit date filter, so a **Select all** export matches the rows you saw.

Who sees what:

| You are | Workspace has the Audits add-on | The column shows |
|---|---|---|
| Owner, Administrator or Manager | Yes | The date, with the hover card, filter and sort |
| Owner, Administrator or Manager | No, or the trial ended | An **Unlock audits** link to the Audits page, and no filter or sort on the column |
| Self-service or Base | Either | Nothing: the column is not offered at all |

## Advanced Filtering System

### Text Fields (Name, Category, Location, etc.)

- **is**: Exact match (e.g., `Location is "Server Room"`)
- **Is in (incl. sub-locations)**: Location only. Matches the location you pick and every location under it. Plain **is** matches the one location and nothing below it. See [Sublocations](/knowledge-base/sublocations-organize-locations-into-hierarchies)
- **is not**: Excludes exact match (e.g., `Category is not "Computers"`). On built-in fields, assets where the field is empty are kept, so `Unit of measure is not "kg"` also lists assets without a unit. On custom text fields, assets with the field empty are left out
- **contains**: Partial match (e.g., `Description contains "wireless"`)
- **matches any**: Multiple exact matches
- **contains any**: Multiple partial matches

### Number Fields (Value)

- **is**: Exact value (e.g., `Value is 1200`)
- **is not**: Excludes value
- **greater than**: Above value (e.g., `Value greater than 5000`)
- **less than**: Below value
- **greater or equal**: Minimum value
- **lower or equal**: Maximum value
- **between**: Value range (e.g., `Value between 1000 and 5000`)

### Date Fields (Created At, Purchase Date, etc.)

- **is**: Specific date
- **is not**: Exclude date
- **before**: Before date
- **after**: After date
- **between**: Date range
- **in dates**: Multiple specific dates
- **Never audited**: [Last audit date](#last-audit-date) only, for assets that have not been counted in a completed audit

### Boolean Fields (Available to Book, Is Portable)

- **is**: Yes/No selection

### Tags

- **contains**: Has specific tag
- **contains all**: Has all specified tags
- **contains any**: Has any of specified tags

### Needs reordering

The **Filter** panel carries a single checkbox, **Needs reordering** (*at or below the min quantity you set*), just above the **Add filter** row. It was called **Low stock only** until October 2026. It narrows the list to [quantity-tracked assets](/knowledge-base/quantity-tracked-assets-and-consumables) whose **Free now** figure has reached or fallen below their **Min quantity**, including pools with nothing free, and it applies immediately rather than waiting for **Apply filters**.

![The advanced asset index Filter popover, with the Needs reordering checkbox described as "at or below the min quantity you set".](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/needs-reordering-filter.webp)

It stacks with everything else, so you can combine it with a location or category filter to see what a single stockroom needs. It also counts toward the filter badge on the **Filter** button and clears with **Clear all**. Add **Min quantity** from the column picker to see each item's threshold next to its **Free now** count. For a narrower question, filter the **Stock status** column instead: **Running low** leaves out pools that have run out entirely, which show **None free**.

### Saved Filters

A filter you use often can be saved and reused. Saved filters are part of the advanced index only.

**Saving a filter**

1. Open **Filter** and build the filter you want.
2. Click **Apply filters**.
3. Click **Save Filter**. It sits next to **Apply filters** in the same panel. It is greyed out until the filter is applied, and hovering it tells you so.
4. Type a name and click **Save**.

A saved filter stores your filters and your sort order. It does not store your columns. Columns stay a separate setting.

**Using a saved filter**

Click **Saved Filters** at the top right of the asset list and pick a name. The button shows how many you have saved. The list has a search box, and a check mark marks the filter you are looking at now.

Each row in the list carries three controls:

- The **star** moves the filter into a **Starred** group at the top of the list
- **Rename** gives it a new name
- **Delete** removes it, after Shelf asks you to confirm

**Rename** and **Delete** appear when you hover the row.

> **You can keep 20 saved filters.** The count is per person, per workspace. At 20, **Save Filter** stays greyed out until you delete one. Two of your saved filters cannot share a name.

**Saved filters are personal**

A saved filter belongs to the person who made it. Your colleagues do not see it, and you do not see theirs.

To give a colleague the same view, apply the filter, copy the page address from your browser, and send it to them. The address carries the whole filter. A location travels as its own ID, so the link opens on the same location for everyone in the workspace. Your colleague opens the link and clicks **Save Filter** to keep a copy.

**Shelf remembers your last filter**

Shelf remembers the last filter you applied in each workspace: the status, sort, custodian, tag, location and column filters, and your page size. It keeps that in the browser you were using, so the list opens on the same filter the next time you come back. Open Shelf in a different browser or on a different computer and the list starts with no filter.

Two things are not kept. The text you typed into the search box is forgotten as soon as you leave the list, so a list never reopens on an old search with nothing to show; a [saved filter](#saved-filters) keeps its search text on purpose. And signing out, or signing in, clears the remembered filters and page size for the whole browser, so the next person at a shared computer starts from a clean list rather than yours. The same rules apply to the bookings and kits lists.

## Asset Model View

If your workspace groups identical units under [Asset Models](/glossary/asset-models), the index can list the models instead of the assets. Click the cube icon beside the list and calendar icons in the toolbar (its tooltip reads **Asset model view**). The button appears in advanced mode only.

![Asset model view: a row for the LED Light 300W class model with 4 assets, 3 in and 1 in custody, and a No model row last with 36 assets and an orange "7 not bookable" chip. Above the table: "40 assets match your filters"](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/asset-model-view.webp)

Each row is one model:

- **Name**, with the model's picture
- **Default category**: the category the model gives a new unit. Units can have been moved to other categories since, so this is the model's default, not a count of where its units sit
- **Assets**: how many of the assets matching your filters carry the model
- **Status**: where those assets are right now, as **in**, **out** and **in custody**. The three add up to the row's asset count. An orange **N not bookable** chip counts the ones with **Available for bookings** switched off. It overlaps the other three rather than adding to them
- **Total value** of those assets

**The counts follow your filters.** Every [filter](#advanced-filtering-system), saved filter and search term applies to this view exactly as it does to the list. The one exception is the **Needs reordering** quick filter: it only concerns quantity-tracked assets, which this view does not count, so switching to the model view clears it. Filter to one location and the view answers "which models do I have here, and how many". A search term matches model names as well as everything else the [search](/features/asset-search) covers, so typing `Dell Latitude` lists that model with its real counts. The line above the table states it, for example *"40 assets match your filters"*.

**Quantity-tracked assets are not counted.** Asset models group individually tracked units only, so for the same filters the model view can show fewer assets than the list view. The info icon beside the count says so.

**Assets without a model** are gathered in a **No model** row, always last. They count toward the asset total but not toward the number of models in the header. That row is a good place to start grouping a fleet: open it, click **View all in list**, select the units, then use **Actions → Update asset model** (see [Grouping a Fleet into an Asset Model](/knowledge-base/using-batch-actions-in-shelf#grouping-a-fleet-into-an-asset-model)). A workspace with no models yet gets a line saying so, with a link to create one for the roles that can.

Click **Name**, **Assets**, **Status** (which sorts by the "in" count) or **Total value** to sort. Switching between the list, availability and model views starts you on page 1, because the pages list different things.

### Seeing the assets behind a count

Click a row's count, such as **4 assets**, and a side panel lists those assets with the columns you have set up for the list. It shows the same assets the count was made from, filters included. The panel loads one page; when more assets matched, it says *"Showing first N of M assets matching your filters"*. The panel's column headers stay in place while you scroll a long list in either direction. When none of the model's assets match your filters, the panel says how many sit outside them, for example *"None match your filters. This model has 52 assets outside them."* **View all in list →** opens the regular list filtered to that model (or to assets with no model), with your other filters kept.

![The side panel for LED Light 300W class: "4 assets match your filters", four lights with their custody, location, status, category and tags, and a "View all in list" button at the bottom](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/asset-model-view-sheet.webp)

### Booking by model from the index

Tick one or more model rows and click **Book selection**:

- **Create new booking** opens the booking form (name, dates, custodian, description and tags) with a row for each selected model and an **Add** box for how many units to reserve. Once both dates are set, each row shows how many units of that model are free in that window, for example *"adding 2 → 2 of 8 available"*; before both dates are set there is no window to measure, so no figure is shown. **Confirm** creates a **Draft** booking that holds those model reservations without naming any units yet, and opens its overview. Reserve it as you would any other booking, then [settle the reservations](/knowledge-base/adding-assets-and-kits-to-a-booking#settling-a-model-reservation) with real units at pickup.
- **Add to existing** lets you pick an open booking (Draft, Reserved, Ongoing or Overdue) and reserve units of each selected model on it. The booking list opens on the bookings that have not ended yet, soonest first, with finished bookings after them, most recently finished first. Once you pick the booking, every row shows what you are adding against what is free for that booking's dates, for example *"2 already reserved · adding 1 → 3 of 8 available"*. Click **Reserve**.

If a model's pool cannot cover the number you ask for in that window, nothing is reserved and Shelf says so under the title **Not enough units**, for example *"Cannot reserve 4 × Dell Latitude 5550. Only 2 can be reserved in this window."*

The **No model** row cannot be selected, since there is no model to reserve units of, and there is no "select all" across pages: a reservation needs a number per model, so you pick the models in front of you. **Book selection** is shown to roles that can create bookings, and not in a personal workspace, which has no bookings.

## Natural and Advanced Sorting

### Natural Sorting

The system uses natural sorting for logical number ordering:

**Traditional Sorting:**
- Scanner 1
- Scanner 10
- Scanner 11
- Scanner 2
- Scanner 3

**Natural Sorting (Shelf):**
- Scanner 1
- Scanner 2
- Scanner 3
- Scanner 10
- Scanner 11

**Benefits:**
- Numbers sort logically within names
- Equipment series appear in proper order
- Serial numbers sort correctly
- Case-insensitive ordering

### Multi-Field (Stacked) Sorting

You can build complex sort orders:

1. Primary sort sets main grouping
2. Secondary sort organizes within groups
3. Additional sorts provide final ordering

To change the order of your sort rules, drag a rule by its ⠿ handle in the **Sort** popover, or Tab to the handle and press **Alt + ↑** or **Alt + ↓**.

**Example:** Sort by Category, then Value, then Name:

```
Computers
  - Laptop ($2,000) - "Dell XPS"
  - Laptop ($1,500) - "HP Elite"
  - Desktop ($1,200) - "iMac"

Networking
  - Switch ($5,500) - "Cisco"
  - Router ($350) - "Netgear"
  - Access Point ($180) - "Ubiquiti"
```

## Batch Actions

### Custody Management

- Release custody from multiple assets
- Assign new custodian to selection
- Perfect for employee offboarding/onboarding

### Tag Operations

- Add tags to multiple assets
- Remove tags from selection
- Great for categorization updates

### Location and Category Updates

- Move multiple assets to new location
- Update category for selected assets
- Useful for department reorganization

### Min quantity

- Select quantity-tracked assets and choose **Set min quantity** to give them all the same low-stock threshold
- Leave the number empty to clear the threshold

### Availability Control

- Mark multiple assets as available/unavailable
- Helpful for maintenance periods

### Archiving

- Archive retired equipment in bulk, or reinstate it from the **Archived** view
- Click the list title (**Assets**) to switch between **Active**, **Archived** and **All**; the view combines with your filters and sorting
- See [Archive and Reinstate Assets](/knowledge-base/archive-and-reinstate-assets)

## Export Capabilities

Select the assets you want (or **Select all X entries** to take the whole filtered set), click **Export selection**, and choose how the file is built:

- **Format**: **Standard** for a readable spreadsheet, or **Import-ready** for a file that uploads straight back into another workspace via **Assets → Import**
- **Columns**: only the columns currently visible in your index, or all of them. **Last audit date** is a Standard-only column; the Import-ready file never carries it
- **QR URL**: a Standard file puts the link each QR code encodes right after **QR ID**, for label printer software. See [Printing labels for assets you already have](/knowledge-base/how-to-print-custom-branded-qr-code-labels-with-shelf#printing-labels-for-assets-you-already-have)
- **Quantities**: a Standard file writes **Total quantity**, **Free now** and **Reserved** as bare numbers and adds **Unit of measure** next to the quantity, even when that column is hidden on screen

A Standard export is perfect for:

- Inventory reports
- Audit preparation
- Budget planning
- Maintenance schedules

Full reference: [Exporting Data from Shelf](/knowledge-base/export-exporting-workspace-data-from-shelf).

### Efficient Filtering

1. Start with broad filters

3. Use date ranges for time-sensitive queries

1. Show only necessary columns

## Troubleshooting

### No Results?

- Check filter spelling
- Try broader criteria
- Verify date formats (YYYY-MM-DD)
- Remove some filters temporarily

### Too Many Results?

- Add more specific filters
- Combine multiple filter types
- Use exact matches instead of contains
- Add date ranges to narrow scope

### Performance Issues?

- Reduce visible columns
- Remove unused filters
- Clear filters after use
- Export large datasets instead of viewing

### Export Issues?

- Verify column selection
- Check filter combinations
- Ensure reasonable dataset size
- Confirm file permissions
