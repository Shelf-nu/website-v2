Shelf automatically generates QR codes for all assets, but many organizations -- particularly those with multi-department operations or strict branding requirements -- need control over label appearance and printing. Using the **Unclaimed Codes** feature, teams can design and batch-produce branded labels in any size, incorporating logos and color schemes, while maintaining full data synchronization with Shelf's asset database.

This workflow leverages Shelf's open QR infrastructure, enabling organizations to integrate their labeling pipeline directly with Shelf's asset identity system.

## What Are Unclaimed Codes?

Unclaimed codes are QR codes generated by Shelf that haven't been assigned to specific assets yet. They exist in the system's QR code pool and can be "claimed" or "consumed" in three ways:


![What Are Unclaimed Codes?](https://cdn.prod.website-files.com/641c35b7e5057648c76fa79f/68e8fb49e3531c0930866332_66aa0b7022eab955bd2a88f9_6638d718009776ef30e6ab91_linking-unclaimed-codes.jpeg)
1. **Create a new asset** -- Scan the code to instantly create an asset record in Shelf
2. **Link to existing equipment** -- Associate the code with an asset already in the database
3. **Swap codes** -- Replace an existing asset's QR code with a new one while preserving history

This flexibility enables pre-production of standardized labels before asset assignment -- critical for scaled operations, vendor integration, and multi-location deployments.

## The Custom Label Printing Workflow

### What You'll Need

- A thermal label printer (or any printer with design software)
- Label design software (usually provided with your printer, or third-party tools like Bartender, NiceLabel, or Avery Design & Print)
- Company logo and branding assets
- Physical label stock in preferred size
- Admin access to Shelf or coordination with workspace administrator
- A **Plus or Team plan** — unclaimed codes can't be requested on the Free plan

### Step 1: Generate Unclaimed Codes

Admins on a **Plus or Team plan** can request unclaimed codes through the Shelf dashboard or via support — unclaimed codes aren't available on the Free plan. Shelf can generate codes in two formats:


![Step 1: Generate Unclaimed Codes](https://cdn.prod.website-files.com/641c35b7e5057648c76fa79f/68e8fb8542e1a2f38a473ff9_Screenshot%202025-10-10%20at%2014.17.44.jpg)
**Option A: CSV File**

- Column 1: URLs that generate QR codes
- Column 2: Asset IDs or SAM IDs
- Additional columns: Any other data fields needed (category, location, custom fields)

**Option B: SVG QR Code Files**

- A folder containing individual SVG files for each QR code
- Accompanying data file with identifiers
- SVGs allow full design customization (colors, borders, embedded graphics)

Shelf can generate thousands or tens of thousands of codes in a single batch -- request enough for anticipated labeling needs for the quarter or year.

### Step 2: Design Your Label Template

Using the label printer's software, create a template that includes:

- **Company logo** -- Positioned per brand guidelines
- **QR code placeholder** -- Sized appropriately for reliable scanning
- **Asset ID or SAM ID field** -- For human-readable reference
- **Optional fields** -- Department, category, handling instructions, compliance markings

**Important design considerations:**

- Ensure the template supports **dynamic data population** -- each label should pull from the next row in the CSV or next file in the folder
- Design for specific label dimensions with proper margins
- Maintain adequate QR code contrast (dark on light background, minimum 3:1 ratio)
- Leave whitespace around QR codes (minimum 4mm "quiet zone")

#### Understanding SAM ID vs Asset ID

- **Asset ID:** The user-visible identifier assigned to equipment (e.g., "LAPTOP-2024-001")
- **SAM ID (Shelf Asset Management ID):** A system-generated unique identifier that persists across asset updates, transfers, or ID changes

For most labeling workflows, Asset ID is sufficient. SAM ID is useful for enterprise integrations where equipment may be renamed but must maintain stable reference across systems.

### Step 3: Test Scannability

Before full production, verify labels meet scanning requirements:

1. Print 5-10 test labels using the final template
2. Scan with multiple devices (smartphones, dedicated scanners, Shelf mobile app)
3. Test from various distances and angles
4. Verify labels scan reliably in typical lighting conditions

**Technical requirements:**

- Minimum 300 DPI print resolution
- QR code size: minimum 20mm x 20mm for handheld scanning
- Contrast ratio: minimum 3:1 (darker QR pattern on lighter background)

If scans fail or require multiple attempts, increase QR code size or adjust printer settings.

### Step 4: Batch Print Your Labels

Configure the printer software to:

1. Read from the CSV file or SVG folder
2. Generate one label per row/file
3. Dynamically populate the QR code and identifier fields
4. Print in batch mode

Once configured, you can produce dozens, hundreds, or thousands of branded labels in a single print session. Because Shelf's QR infrastructure is open and portable, asset labels are never locked into a proprietary format -- organizations maintain full control over their labeling pipeline.

### Step 5: Apply and Claim Labels

Standard operating procedure becomes:


![Step 5: Apply and Claim Labels](https://cdn.prod.website-files.com/641c35b7e5057648c76fa79f/68e8fb930ffdb3112253f443_66aa0b7022eab955bd2a88f6_6638dae4cbed01e73c2e4288_linking-unclaimed-codes-to-existing.jpeg)
1. **Receive or identify equipment** requiring asset tracking
2. **Apply a pre-printed label** to the equipment in a consistent location
3. **Scan the QR code** using the Shelf mobile app, web interface, or integrated scanner
4. **Create or link the asset** -- The unclaimed code is now consumed and permanently associated with that asset

**Traceability:** All code assignments, swaps, and claims are logged in the asset history for audit traceability. This ensures compliance with inventory audits, equipment handovers, and change management policies.

## Printing Labels for Assets You Already Have

Unclaimed codes are for labels you print before the assets exist. For assets already in Shelf, each one already has a QR code, and you can get its data straight from Shelf for your label software, without asking support.

Label software such as Brady Workstation, P-touch Editor, Dymo Connect, Bartender or NiceLabel builds the QR code itself from a column of URLs. Shelf gives you that column in three places:

1. **The bulk QR download.** Available on every plan. On the asset list, select the assets, then **Actions → Download QR Codes**. Besides the QR images (in a `qr-codes/` folder), the `.zip` holds a **`labels.csv`** at its root with one row per asset, in the same order as the images: `Asset name`, `SAM ID`, `QR ID`, `QR URL`, `Category`, `Location`. Point your label template at that file and map its QR code element to the `QR URL` column.
2. **The asset export.** On the advanced asset index, **Export selection** in the **Standard** format writes a **QR URL** column right after **QR ID** (whenever QR ID is in the export), next to every other column you export, custom fields included. Use this when your label needs more than the six `labels.csv` columns. Exporting assets is part of the Plus and Team plans.
3. **The Asset Inventory report.** Its CSV export carries a **QR Code URL** column after **QR Code ID**. Reports are part of the Plus and Team plans.

Every URL has the form `https://eam.sh/<QR ID>`, the same link the Shelf QR code encodes, so a label printed from it scans exactly like the Shelf label. An asset without a QR code has an empty cell.

A few details that matter when the file lands in label software:

- `labels.csv` is UTF-8 with a byte order mark, so accented and non-Latin names come through intact.
- A value that would run as a spreadsheet formula, such as a name starting with `=`, gets a leading `'` so it is printed, not executed. A plain measurement such as `-20C Freezer` or `+5V PSU` is left exactly as typed.
- **Location** is the asset's first location. A quantity-tracked pool kept at several locations shows one of them.

## Frequently Asked Questions

### Design and Printing

**Can I change how the QR codes look?**
If using SVG files, yes. You can modify colors, add borders, or embed them in custom designs. The QR code pattern itself must remain intact for scanning reliability. Maintain a minimum 3:1 contrast ratio.

**What printer types work with this workflow?**
Any printer with design software capable of reading CSV or image files: thermal label printers (Zebra, Dymo, Brother), inkjet label printers, laser printers, or commercial print services. The workflow is printer-agnostic.

**What if my labels don't scan reliably?**
Increase QR code size, verify 300+ DPI resolution, check contrast ratio, and ensure adequate quiet zone (whitespace) around the code. Test with multiple scanning devices.

### Code Management

**How many unclaimed codes can I generate?**
There's no practical limit. Shelf can generate thousands or tens of thousands of unclaimed codes in a single batch. Generate enough for anticipated needs -- excess codes can be saved indefinitely.

**Do unclaimed codes expire?**
No. Unclaimed codes remain valid indefinitely until they're scanned and claimed. Unused labels can be saved for future equipment or discarded without penalty.

**What happens if I print labels but never use them all?**
No issue. Unused labels with unclaimed codes can be stored for future use or discarded. There's no cost or system impact for unused codes -- they simply remain in the QR code pool until claimed.

**Can I reuse a code if I remove a label?**
Once a code is claimed and associated with an asset, it's permanently linked to that asset's history. If you need to replace a label, use the swap function to assign a new code while preserving the asset's record.

### Data Fields

**What if I want to print the asset name instead of just the ID?**
`labels.csv` already carries the asset name, SAM ID, category and location. For anything else, such as a serial number or another custom field, use a Standard asset export, which includes every column you choose plus the QR URL. Configure the label template to display the fields most relevant to your operations.

**How do I handle labels for kits with multiple components?**
You have two options: (1) Generate individual codes for each kit component, or (2) Use Shelf's kit management feature to associate a parent code with child asset codes. Both approaches are supported.

### Existing Assets

**Can I export QR codes for existing assets?**
Yes. Select the assets on the asset list and use **Actions → Download QR Codes** to get a zip file of their codes. You can choose whether to render the Asset ID or SAM ID on the exported codes. The zip also holds a `labels.csv` with each asset's QR URL, for label software. See [Printing labels for assets you already have](#printing-labels-for-assets-you-already-have).

**Can I get the URL each QR code encodes?**
Yes, without contacting support. It is the `QR URL` column of `labels.csv` in the QR download, the **QR URL** column of a Standard asset export, and the **QR Code URL** column of the Asset Inventory report. Each one reads `https://eam.sh/<QR ID>`.

## Getting Started

Ready to implement custom label printing for your organization?

1. **Determine your requirements** -- Label size, material, design elements, data fields
2. **Request unclaimed codes** -- Through your Shelf admin dashboard or support (available on the Plus and Team plans — not Free)
3. **Design your template** -- Using your label printer's software
4. **Run a test batch** -- Verify scannability and print quality
5. **Scale to production** -- Print labels as needed for ongoing operations

Your Shelf workspace administrator can coordinate code generation and provide CSV or SVG files. For questions about label materials, design templates, or Shelf's printing service, visit [store.shelf.nu](https://store.shelf.nu).
