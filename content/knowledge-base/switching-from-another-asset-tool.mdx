This guide is for teams that already run a dedicated asset or equipment tool and want to move to Shelf without starting over. It covers the four things every switch comes down to: getting your data out of the old tool, checking how its columns map to Shelf's fields, keeping the labels that are already stuck to your gear, and what a migration of about 1,000 assets looks like in practice.

If you are coming from a spreadsheet rather than a tool, the [CSV import guide](/knowledge-base/importing-assets-to-shelf-csv-guide) is the shorter path. Everything below still applies, but you can skip the export step.

## Before you start

**What comes across.** Shelf's import creates assets with their category, location, kit, tags, custodian, value, image link, and any number of extra fields. Categories, locations, kits, tags, asset models and custodians are matched by name and created on the fly, so you do not have to set anything up first.

**What stays behind.** Your old tool's activity history, past bookings and check-out logs do not import. Shelf starts a clean history from the day you switch. If some of that history matters, carry the important bits as extra fields on each asset: previous ID, last service date, notes. Photos only come across if your old tool can export a public image link per asset.

**Plans.** CSV import is available on the paid plans and during the free Team trial. Keeping your existing barcode or QR stickers needs the [Alternative Barcodes](/knowledge-base/alternative-barcodes) add-on, which attaches to the Team plan and comes with a one-time 7-day free trial per workspace. If you only want to re-label everything with Shelf's own QR codes, you do not need the add-on.

**Who should do it.** Importing needs an Owner or Admin in the workspace. Plan on one person owning the migration end to end; it keeps the column mapping consistent.

## Step 1. Export everything from your old tool

Export your full asset list as CSV, or as a spreadsheet you can save as CSV. Include every column, even the ones you think you will drop. It is easier to delete columns later than to go back for one you missed.

Three columns deserve extra attention:

- **The label value.** Most tools have a column called asset tag, barcode, label, code or ID that holds what is printed on each sticker. This is the column that lets you keep your stickers. Make sure it is in the export.
- **The current holder.** Whoever has the item right now. Shelf imports this as the custodian, so people walk away with the same equipment they had before the switch.
- **Serial numbers and purchase details.** These become extra fields in Shelf. Keep them.

Open the export and check that it has one row per physical item. Some tools export one row per model with a quantity column. For equipment you lend out and track one by one, you want one row per item, each with its own label value. Stock you count rather than track piece by piece, such as cables, batteries or tape, can stay as one row with a quantity: the import asks how those rows should be tracked (see Step 2).

## Step 2. Check how your columns map

You do not have to rename anything. Upload the export as it is: when you click **Continue**, Shelf shows **Check how your columns map**, one row per column of your file with a few sample values and the Shelf field it proposes. It recognises more than 150 headings that other tools and spreadsheets use, Sortly's, Asset Panda's and Snipe-IT's among them, so most columns arrive already placed. A green dot is a sure match, an amber dot a guess to check. Change any row with its dropdown, send it to **Custom field...**, or set it to **Skip**. Nothing is imported until you have checked the table and the preview after it.

![Check how your columns map for a Sortly-style export: Entry Name to Title, Unit to Unit of measure, Min Level to Low-stock alert at, Primary Folder to Location, and Sortly ID skipped with an amber dot](https://qliecghuzfchfjwaisyx.supabase.co/storage/v1/object/public/website-images/knowledgebase/import-column-mapping.webp)

A few things the review does for you:

- **It asks how stock is tracked.** When a column goes to **Quantity** and none says whether a row is an individual asset or stock (every Sortly export is like this), it asks: **Individual assets**, **Stock, returned after use**, or **Stock, used up**.
- **It skips the old tool's own ids.** A column such as *Sortly ID* is set to **Skip**. If people look items up by that number, set it to **Custom field...** with a name like *Previous ID* instead.
- **It reuses your custom fields.** A column with the same name as a custom field you already have goes to that field, with its type.
- **It warns about values the import will refuse**, such as dates written DD/MM/YYYY.

The [CSV import guide](/knowledge-base/importing-assets-to-shelf-csv-guide#checking-how-your-columns-map) describes the review in full. Prefer to prepare the file yourself? Download the template from **Assets → Import** (there is a version with barcode columns once the add-on is on): a file with Shelf's own headings goes straight through the review with every row green.

Where your columns usually end up:

| Column in your old tool | Shelf header | Notes |
|---|---|---|
| Name, Asset name, Item | `title` | The only required column |
| Description, Notes, Details | `description` | Free text |
| Category, Type, Group | `category` | Created if it does not exist |
| Location, Site, Room, Storage | `location` | Created if it does not exist |
| Assigned to, Checked out to, Holder | `custodian` | Matched by name, not email; a non-registered team member is created when the name is new |
| Tags, Labels, Keywords | `tags` | Several per cell, separated by commas |
| Kit, Bundle, Case, Parent | `kit` | Assets with the same kit name are grouped into one kit |
| Purchase price, Cost, Value | `valuation` | Plain number, `.` as the decimal mark, no currency symbol |
| Photo, Image URL | `imageUrl` | Must be a public `http(s)` link that returns an image |
| Model, Product | `assetModel` | Groups identical units under one model; created if missing |
| Barcode, Asset tag, Label, QR text | `barcode_Code128`, `barcode_Code39`, `barcode_DataMatrix`, `barcode_ExternalQR` or `barcode_EAN13` | See Step 3 |
| Serial number | `cf:Serial number,type:text` | Common names such as *Serial No.* are proposed as this field; any other column can become an extra field through **Custom field...** |
| Purchase date, Warranty until | `cf:Purchase date,type:date` | Dates must be `YYYY-MM-DD` |
| Old ID, Legacy number | `cf:Previous ID,type:text` | Skipped unless you pick **Custom field...**. Worth keeping so people can still find items by the number they know |
| Status, Available / Checked out | **Skip** | Shelf sets status itself; a row with a `custodian` imports as "In custody", everything else as "Available" |
| Created, Last modified, History | **Skip** | Not imported |

The mapping only renames columns; it never changes a value. A few rules about the values themselves still catch people out:

- **Every row needs a `title`.** The file is checked before anything is created, and a row without one is reported back to you.
- **Extra fields** are created with the type you pick in the review: `text`, `multiline text`, `option`, `boolean`, `date`, `amount` or `number`. If you prepare the file yourself, the header pattern is `cf:Field name,type:text`, in double quotes in a comma-separated file because it contains a comma.
- **Dates** must be `YYYY-MM-DD`. Any other format stops the import with a clear error naming the row.
- **Numbers** carry no currency symbols or thousands separators. `1250.50` works, `$1,250.50` does not.
- **Save as UTF-8.** In Excel choose "CSV UTF-8" when saving, or accented names come through garbled.
- **No more than 10,000 rows and 200 columns per file.** A bigger file is refused with a message saying which limit it hit, before anything is created.

The full column reference, with every rule and example, is in the [CSV import guide](/knowledge-base/importing-assets-to-shelf-csv-guide).

## Step 3. Keep the stickers that are already on your gear

Re-labelling a thousand items is the part of a migration nobody wants. You usually do not have to. With the [Alternative Barcodes](/knowledge-base/alternative-barcodes) add-on, Shelf stores the value printed on each existing sticker next to the asset, and scanning that sticker with Shelf's scanner opens the asset, exactly like a Shelf QR code would.

**Pick the right column for your label type.** Look at one sticker:

- A one-dimensional barcode (parallel lines) is almost always **Code 128** or **Code 39**. Put the printed value in `barcode_Code128` or `barcode_Code39`. If you are not sure which, scan it with any barcode app on your phone; the app names the format.
- A small square code made of dots is a **DataMatrix**. Use `barcode_DataMatrix`.
- A retail-style 13-digit barcode is an **EAN-13**. Use `barcode_EAN13`.
- A QR code printed by your old tool is an **External QR**. Use `barcode_ExternalQR`.

**External QR codes need extra care.** A QR sticker from another tool usually encodes a web link, something like `https://example.com/a/ABC123`, while the tool's export often lists only the short part, `ABC123` or `example.com/a/ABC123`. Shelf matches a scanned External QR code against the stored value exactly, character for character. If the stored value is the short form and the sticker encodes the full link, the scan will not find the asset.

So before you import:

1. Scan one of your old QR stickers with any phone QR app (the built-in camera app works on most phones) and copy the exact text it shows.
2. Make the `barcode_ExternalQR` column hold that same text for every asset, with the same `https://`, the same `www.`, the same trailing slash, and the same capital letters. Case is kept exactly as you import it for External QR values.
3. Import five assets first and scan their stickers in Shelf. If they open, import the rest. If they do not, compare the stored value with what your phone showed and fix the column.

For Code 128, Code 39, DataMatrix and EAN-13 values this matching problem does not exist. Shelf stores them in upper case and finds them regardless of how they were typed.

**Uniqueness.** Every barcode value must be unique in your workspace. If two rows in your file share a value, or a value already exists in the workspace, the import tells you which rows before creating anything.

**Items without a usable sticker** get a Shelf QR code automatically. Leave their barcode cells empty and print Shelf labels for them after the import.

## Step 4. Run a small test import first

Make a copy of your file with five to ten rows that cover your variety: an item in a kit, one with a custodian, one with an extra field of each type, one with a barcode of each type you use.

1. In Shelf, go to **Assets → Import**.
2. Choose the file and click **Continue**. Shelf shows where each of your columns will go. Check the amber rows, change any that look wrong, or set them to **Skip**, and answer the tracking question if it appears.
3. Click **Preview import**. Shelf checks the whole file first. If anything is wrong you get a list of every problem with its row number, and nothing is created. Fix the rows and upload again.
4. Read the preview: it lists the categories, locations, custodians and extra fields the file will create. A misspelt location shows up here as a new one.
5. Click **Import N assets**, type `I AGREE` and click **Import**.
6. When it finishes, open the assets and check the category, location, custodian, extra fields and barcodes landed where you expected. Scan a sticker.

Delete the test assets if you want a clean start, or keep them and remove those rows from the main file.

## Step 5. Import the rest: what to expect for about 1,000 assets

Once you confirm, the import runs in the background on Shelf's side. Your browser does not have to wait for it.

**One file is fine.** A file of 1,000 assets goes in as it is; the limit is 10,000 rows per file. You do not need to split it for speed.

**You can leave the page.** The import page shows a progress bar, a small progress card follows you around Shelf, and you get an email when the import is complete. Imports with many image links take longest, because every image is downloaded.

**If it stops, resume it, do not upload again.** The rows already imported stay, and nothing is imported twice. Open the import with **Open import** in the email, or **View progress** on the progress card, and click **Resume import**. Uploading the same file a second time would create every asset again.

**Read the warnings.** If something changed in Shelf after the preview, for example a barcode was given to another asset in the meantime, that row is still imported with the value left out, and the import page lists it.

**If you split the file anyway**, import kits together, so a kit's assets are created in one file and inherit the same custodian, and keep rows that share an extra field in the same file the first time that field appears, so it is created once with the right type. One import runs at a time, so start the next part when the previous one finishes.

A whole migration of 1,000 assets, including checking the mapping, usually fits in an afternoon. The import itself is the quick part; cleaning the export is where the time goes.

## After the import

- **Scan a handful of stickers** from different parts of the inventory. If they open the right asset, your label mapping is correct everywhere.
- **Print Shelf labels** for items that had no sticker or an unreadable one. Shelf generated a QR code for each of them during import.
- **Invite your team.** Custodians who were created from your file as non-registered team members can be [converted to real users](/knowledge-base/converting-non-registered-members-nrms-to-users) when you invite them with the same name.
- **Keep the old tool read-only for a few weeks.** You will want to look something up in its history. Cancel it once nobody has opened it in a month.
- **Switch on what you moved for.** [Bookings](/knowledge-base/introduction-to-bookings), [custody](/knowledge-base/custody-feature-for-long-term-equipment-lend-outs) and [audits](/knowledge-base/run-your-first-audit) work on imported assets straight away.
