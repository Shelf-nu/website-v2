> **Availability.** SCIM is an **opt-in feature for self-hosted Shelf deployments** and is **not currently available on Shelf Cloud**. It builds on Shelf's SSO, so a working [SSO connection](/knowledge-base/sso-with-google-workspace) is required before SCIM can provision anyone.

## What SCIM Does

Shelf's SSO already creates accounts the first time someone signs in (just-in-time provisioning). That works well, but it means a user does not exist in Shelf until they log in for the first time. If an administrator needs to assign custody of an asset to a colleague who has not signed in yet, there is no account to assign it to.

SCIM (System for Cross-domain Identity Management) closes that gap. With SCIM enabled, your identity provider pushes user lifecycle changes to Shelf directly, so accounts are ready **before** the person's first login:

- **Create** users in a workspace as they are added to the mapped groups in your IdP.
- **Update** a user's details (for example, a name change) and Shelf keeps the account in sync.
- **Deactivate** users when they are removed or disabled in your IdP, so access is revoked centrally.

SCIM only provisions users whose email domain matches the workspace's **verified SSO domain**. A user provisioned by SCIM is created in Shelf; when that person later signs in through SSO, Shelf matches them to the account SCIM already created. If a user is deactivated via SCIM, signing in through SSO will not restore their access.

## Requirements

Before you can turn SCIM on:

1. **A self-hosted Shelf deployment.** SCIM is controlled by a server-side deployment flag and is not offered on Shelf Cloud.
2. **SSO already configured** for the workspace, with a verified SSO domain. See [SSO with Google Workspace](/knowledge-base/sso-with-google-workspace) for the general SSO flow; the provider-specific screens and attribute mappings differ for **Microsoft Entra ID**, **Okta**, and other SAML 2.0 providers.
3. **Workspace owner access.** SCIM tokens are managed by the workspace owner.

## How to Set It Up

### 1. Enable SCIM on your deployment

SCIM stays off until it is explicitly enabled. On your self-hosted instance, set the `ENABLE_SCIM` configuration flag to `true`. While it is off, the SCIM API returns `404` and the SCIM section in workspace settings is hidden. Full configuration details are in the [self-hosting documentation](https://docs.shelf.nu).

### 2. Generate a SCIM token

Once SCIM is enabled, the workspace owner can create a bearer token that your identity provider will use to authenticate:

1. Go to **Settings → General**.
2. Find the **SCIM tokens** section.
3. Click **Generate token** and give it a label.
4. **Copy the token immediately** — it is shown only once. Store it securely; if you lose it, delete the token and generate a new one.

You can keep several tokens (for example, one per identity provider) and delete any token to immediately revoke the integration that uses it.

### 3. Connect your identity provider

In your IdP's provisioning settings, point the SCIM connector at your Shelf deployment:

- **SCIM base URL:** `https://<your-shelf-domain>/api/scim/v2`
- **Authentication:** Bearer token — paste the token you generated in step 2.

Shelf exposes the standard SCIM 2.0 discovery endpoints (`ServiceProviderConfig`, `ResourceTypes`, and `Schemas`) under that base URL, so most identity providers can validate the connection automatically. Map the groups you want provisioned into Shelf and start the sync from your IdP.
