Who a person may put on a booking is decided by their role. Administrators and Owners can name anyone in the workspace; Base and Self-service members book for themselves, so the **Custodian** field offers them their own name and stops there. That is how the web has always behaved.

The [Shelf Companion](/mobile-app) app applied only part of that rule. Its custodian picker — the one behind **New booking** and an edited booking — now resolves through the same server-side rule the web pickers use, so the two platforms offer the same names to the same person. Searching inside the picker still searches only what that person is already allowed to see.

The workspace's **custody visibility** setting is unrelated and does not widen the list. It governs whose custody a person can *see*; whom they may *assign* stays with their role. See [what the toggles never reach](/knowledge-base/configure-what-self-service-and-base-users-can-see#what-the-toggles-never-reach).

**Nothing to install.** This is a server-side change, so every phone that already has Shelf Companion picked it up as soon as it deployed — there is no app update to wait for. Administrators and Owners see no difference.
