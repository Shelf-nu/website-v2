Extending a running booking used to be a guess. You picked a date, submitted, and if another reservation held any of the items the refusal listed the booking names and nothing else, so you opened each one, compared item lists by hand and tried a shorter date.

**Change end date** now opens already saying how far you can go: *"No other booking has these items reserved until 8 Nov 2026, 09:00. After that, Camera day needs Cam 1, Cam 2."*, with a **Use …** button that ends the booking just before that. A submit past that point is refused with each booking in the way, the items it reserves and the day it starts. And while the booking runs, every item row that another booking has reserved carries an amber **Needed** badge saying from when, with the booking named in its tooltip.

The same change fixes a false refusal. A [quantity-tracked](/knowledge-base/quantity-tracked-assets-and-consumables) item was treated like a named unit, so a booking holding 3 of 30 cables could be refused over four bookings that each reserved one cable. Pooled stock is now measured as a pool over the added days and refused only when the units really run short, with the numbers named. On the phone, the extend refusal now lists the shared items after each booking name.
